Run RAG11 from scratch

This page is the full teardown-and-rebuild checklist for RAG11: wipe the Supabase schema, wipe the locally cached source PDFs and generated chunk files, then re-run the pipeline from an empty database and an empty disk cache — ending with live question answering against freshly ingested textbooks. Use it when you want a guaranteed-clean rebuild rather than an incremental re-run; for first-time environment setup (Python venv, .env API keys), see README.md instead.

Step 3 (Mac file-descriptor limit) is independent of the database/folder steps around it — it is a one-time, system-wide macOS setting, not a per-run cleanup step. It is placed here because it is the natural point to confirm it before a long ingestion run, and it is safe to re-run.

Steps 1–2

Reset the database

Both scripts run in the Supabase Dashboard → SQL Editor for your project. Paste the full file contents and click Run.

1

sql/drop_all_tables.sql destructive

Supabase Dashboard → SQL Editor

Drops rag11_data_sources, rag11_chunks_parent_table, rag11_chunks_child_table (cascading their indexes, RLS policies, and foreign keys) and both RPC functions, match_rag11_child_chunks and get_rag11_parent. Nothing is left behind for create table if not exists to guard around, so step 2 becomes a completely clean rebuild.

WarningThis is unrecoverable — every ingested row (all embeddings) is gone. If you only want to clear rows and keep the schema for a fresh stage1_2_eda_load_chunks.ipynb run, use sql/delete_chunks_data.sql instead and skip straight to step 4.
-- paste the full contents of sql/drop_all_tables.sql, then Run
drop function if exists public.match_rag11_child_chunks(...);
drop table if exists public.rag11_chunks_child_table cascade;
drop table if exists public.rag11_chunks_parent_table cascade;
drop table if exists public.rag11_data_sources cascade;
-- sanity check at the bottom of the file should return zero rows
2

sql/create_sql_tables.sql

Supabase Dashboard → SQL Editor

Recreates the schema from an empty database: enables pgvector, creates all three tables (the shared rowGUID / rowOwnerGUID / rowParentGUID / orderInList / rowJSON shape), the HNSW cosine vector index and GIN full-text index on the child table, the match_rag11_child_chunks / match_rag11_child_chunks_keyword / get_rag11_parent RPCs, and permissive POC-stage RLS policies/grants. Safe to re-run — every statement is idempotent (create ... if not exists, create or replace function).

Step 3

Run the Mac settings script in Terminal

3

stage1_0_run_mac_settings.command

Terminal, from the project root (or double-click in Finder)

Raises macOS's system-wide open-file ceiling (default often 256 per process) to 65536 soft / 200000 hard via a LaunchDaemon, permanently and for every app — not just this project — so a long, highly-parallel ingestion run doesn't fail with [Errno 35] Resource temporarily unavailable. It re-launches itself with sudo, so you'll be asked for your Mac password.

cd /Users/mgtimber/CV26/RAG11
./stage1_0_run_mac_settings.command
NoteOne-time and idempotent — safe to re-run. It touches only this Mac's system-wide file-descriptor limit; it never touches the venv, .env, or Jupyter. If Terminal/PyCharm/Jupyter were already running, restart them afterwards so they pick up the new limit.
Step 4

Delete the local cache folders

4

Delete stage1_eda_input/ and stage1_eda_output/ destructive

Finder, or Terminal from the project root

Both stage 1.1 (download) and stage 1.2 (ingest) are idempotent by design — they skip any PDF already cached in stage1_eda_input/ and resume from checkpoints in stage1_eda_output/_checkpoints/. Deleting both folders is what forces a truly clean rebuild: every one of the 17 source PDFs (~650 MB) is re-downloaded from Google Drive, and every parent/child chunk JSON file (~38 MB) is regenerated from scratch rather than reused.

cd /Users/mgtimber/CV26/RAG11
rm -rf stage1_eda_input stage1_eda_output
WarningThis deletes local files only — it does not touch Supabase — but it is unrecoverable for anything not already committed. If either folder holds work you haven't pushed with save_to_github.command, back it up first.
Steps 5–6

Rebuild the knowledge base

Open each notebook in Jupyter/PyCharm and run every cell top to bottom.

5

stage1_1_extract_and_chunk.ipynb

Jupyter / PyCharm, run all cells

Lists the 17 source PDFs from GOOGLE_DRIVE_SOURCES_FOLDER, downloads any missing ones into stage1_eda_input/source<N>/ concurrently via gdown, extracts per-page text, detects sections with a per-source algorithm (stage1_1_eda_packages/, one module per PDF), and writes hierarchical parent_chunk-N.json / child_chunk-parentN-chunkM.json files plus a source_row-N.json manifest per source to stage1_eda_output/. Runs against a fresh cache after step 4, so every source downloads and re-chunks from zero.

6

stage1_2_eda_load_chunks.ipynb

Jupyter / PyCharm, run all cells

Loads the chunk JSON files written in step 5, embeds every child chunk with Voyage AI (voyage-3, input_type="document") in parallel batches with retries, and upserts source/parent/child rows into the tables step 2 created. Deterministic uuid5 row ids and per-row checkpointing mean this is a safe, resumable upsert even against the empty schema from step 1–2.

RecommendedRun stage1_9_eda_verify_all_data.ipynb next (optional, not one of the 7 core steps) to confirm zero missing/orphaned rows and that every child chunk has a valid 1024‑dim embedding before moving on to step 7.
Step 7

Ask questions and check the answers

7

Run a stage2_ask_examples*.ipynb notebook

Jupyter / PyCharm, run all cells

Each notebook embeds a small set of hand-picked nutrition questions with Voyage AI (input_type="query"), retrieves matching child chunks from the freshly rebuilt tables, and asks Claude Sonnet to answer strictly from that retrieved text — printing a short Yes/No summary, the full explanation, and page citations per question. Pick whichever retrieval mode you want to exercise:

Notebook▲ Retrieval mode▲ What it demonstrates▲
stage2_ask_examples1.ipynbPlain denseBaseline: vector search only, straight through to a grounded answer.
stage2_ask_examples2_rerank.ipynbDense + rerankOver-fetches a wide pool, then re-scores with Voyage's rerank-2 cross-encoder.
stage2_ask_examples3_hybrid_search.ipynbHybrid (dense + keyword)Fuses dense and full-text keyword search via Reciprocal Rank Fusion.
stage2_ask_examples4_parent_chunk_expansion.ipynbDense + parent expansionSwaps each winning child chunk for its full parent section before generation ("small-to-big").
stage2_ask_examples5_hypothetical_document_embedding.ipynbHyDEEmbeds a Claude-drafted hypothetical answer instead of the bare question, then searches with that.

A working rebuild should reproduce the sample question/answer trace in the Sample Data section below — if stage2_ask_examples1.ipynb's first sample question returns a confident, cited "Short answer: Yes" for vitamin C, steps 1–6 succeeded.
