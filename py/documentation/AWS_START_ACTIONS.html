AWS start actions — Bedrock OCR credentials

This page is the full sequence to get py/lrm/data/recognize.py running with OCR_PROVIDER_NAME=ocr_with_aws — page recognition via Claude on AWS Bedrock instead of Gemini. AWS has no single "OCR API key": you need an IAM access-key pair scoped to Bedrock, plus a one-time console invocation that auto-enables the Claude model in your account. Everything below either runs in the AWS Console (no CLI equivalent for that first invocation) or is a copy-paste aws CLI command.

Steps 1–2

AWS Console: account + model access

Both of these are console-only — there is no aws CLI command that grants Bedrock model access.

1

Sign up / log in console only

console.aws.amazon.com

If you don't have an AWS account yet, create one at aws.amazon.com (needs a card on file; Bedrock is pay-per-token, no separate OCR free tier). Log in to the AWS Console as the root user — root is only used for this one-time setup.

2

Invoke the Claude model once, from the Playground console only

Console → Bedrock → Model catalog → Playground

AWS retired the old "Model access" checkbox page — serverless models like Claude now auto-enable account-wide, per region, on their first invocation. Don't make that first call from the CLI cold, though: Anthropic models can still prompt a one-time "use case details" form on first use — often before you've even picked a specific model — and a raw CLI call just fails with an opaque error instead of showing it. Do the first call here instead: Bedrock → Model catalog → select the Claude model you want → Open in Playground → send one test message (e.g. "hello"). If the use-case form appears, fill it in right there.

Region-scopedThis enables the model only in the region you did it in. Do this in the exact region you'll put in AWS_REGION later (e.g. us-east-1).
Marketplace noteA few Bedrock models are served via AWS Marketplace, where the first invocation must come from a user with Marketplace subscribe permissions. Doing this step as the root user sidesteps that entirely — it always has full permissions.
Not always instantThe use-case form can show "Your account is not authorized to perform this action" and refuse to submit from the console. If that happens, open an AWS Support case at console.aws.amazon.com/support/home (an "Account and billing" case is free, no paid Support plan needed) with the same use-case details, and wait for manual review — this can take minutes to a business day, not always instant. You can still do steps 3–5 (CLI + IAM user) while waiting; only step 2's own test message and step 8's real run need the approval to land first.
Step 3

Install and bootstrap the AWS CLI

3

Install the CLI, then bootstrap one admin credential

Terminal, once

Install (macOS):

brew install awscli

Verify:

aws --version

The CLI needs some credential before it can create your app's own credential. Cleanest bootstrap: Console → IAM → IAM Users (may just say "Users" in older console versions) → Create user → name it bootstrap-admin → attach policy AdministratorAccess → Security credentials tab → Create access key → choose "Command Line Interface (CLI)" → copy the Access Key ID + Secret. Then:

aws configure

Paste the bootstrap admin's Access Key ID, Secret, region (e.g. us-east-1), and output format json when prompted.

Steps 4–5

Create the app's real IAM user (copy-paste)

This is the credential that actually ends up in .env — scoped to just Bedrock invocation, not full admin.

4

rag11-bedrock IAM user + scoped policy

Terminal, using the bootstrap-admin credentials from step 3

Create the user:

aws iam create-user --user-name rag11-bedrock

Create a policy limited to invoking Bedrock models:

aws iam create-policy --policy-name LRM11BedrockInvoke --policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":["bedrock:InvokeModel","bedrock:InvokeModelWithResponseStream","bedrock:ListFoundationModels"],"Resource":"*"}]}'

This prints an ARN like arn:aws:iam::123456789012:policy/LRM11BedrockInvoke — copy your account ID from it for the next command.

Attach the policy (replace <ACCOUNT_ID>):

aws iam attach-user-policy --user-name rag11-bedrock --policy-arn arn:aws:iam::<ACCOUNT_ID>:policy/LRM11BedrockInvoke
5

Create the access key secret shown once

Terminal
aws iam create-access-key --user-name rag11-bedrock
Copy nowThe output's SecretAccessKey is shown exactly once. Copy both AccessKeyId and SecretAccessKey somewhere safe immediately — you cannot retrieve the secret again later, only rotate it.
Step 6

Find the exact Bedrock model ID

6

List available Anthropic models instead of guessing the ID

Terminal, still using bootstrap-admin credentials

Model ID strings vary by region and change over time — don't hand-type one. List them:

aws bedrock list-foundation-models --region us-east-1 --by-provider anthropic --query "modelSummaries[].modelId" --output table

Copy the ID of the Claude model you invoked in the Playground in step 2 — that exact string is your BEDROCK_MODEL_ID.

Step 7

Fill in .env

7

Four new variables, from steps 5 and 6

Project root → .env (see .env.sample)
OCR_PROVIDER_NAME=ocr_with_aws
AWS_ACCESS_KEY_ID=<AccessKeyId from step 5>
AWS_SECRET_ACCESS_KEY=<SecretAccessKey from step 5>
AWS_REGION=us-east-1
BEDROCK_MODEL_ID=<modelId from step 6>
NoteGOOGLE_AI_API_KEY stays set too — translate.py always uses Gemini for translation regardless of OCR_PROVIDER_NAME; only page recognition in recognize.py switches provider.
Step 8

Verify before a full run

8

Confirm the credential works, then test one page

Terminal

Confirm the new (scoped) credential authenticates:

AWS_ACCESS_KEY_ID=<AccessKeyId> AWS_SECRET_ACCESS_KEY=<SecretAccessKey> AWS_REGION=us-east-1 aws sts get-caller-identity

If that returns your account/user info rather than an error, the credential is live. Then run the real pipeline against a single page:

python py/lrm/data/recognize.py --pdf py/lrm/data/input/fr/<yourbook>.pdf --lang fr --start 1 --end 1
WorkingA successful run prints ok page 1: N blocks, M words and writes output/fr/<book>/json/page_0001.json with the same schema Gemini would have produced.
Recommended, not required

Delete the bootstrap admin key

✓

Retire bootstrap-admin do this yourself in the console

Console → IAM → IAM Users → bootstrap-admin → Security credentials

Once step 4–5 succeeded, the bootstrap-admin user with full AdministratorAccess is no longer needed and is a standing risk if its key ever leaks. Deactivate or delete its access key in the console. rag11-bedrock's narrow policy is all the app actually needs going forward.
