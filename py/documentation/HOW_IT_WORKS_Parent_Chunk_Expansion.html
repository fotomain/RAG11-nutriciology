Parent-chunk expansion: small-to-big context

Parent-chunk expansion swaps a winning child chunk (small, precise, good for matching) for its parent chunk (the full section it was carved from, good for answering) right before Claude sees it. It fixes the case where the best-matching excerpt is too narrow to answer the whole question, even though it matched perfectly. No new table, index, or migration is needed — lrm_page_table and the rowParentGUID foreign key already exist.

1 lookup per distinct parent
0 schema changes
Dedup built in
6000 chars default truncation cap
Composable with hybrid + rerank
Motivation

The problem in plain terms

Child chunks are deliberately small (~300–500 tokens) so they match a question precisely. That precision has a cost: a small chunk sometimes doesn't carry enough surrounding context to answer the question fully.

Example:

Question: "How does soluble fiber's effect on LDL cholesterol differ from insoluble fiber's effect?"
  • Say the winning child chunk (after rerank, or hybrid, or plain vector search) is just two sentences: "Soluble fiber binds bile acids in the gut, which forces the liver to pull more LDL cholesterol from the blood to make more bile acids."
  • That's a great match for the question — but it says nothing about insoluble fiber. The comparison Claude needs is incomplete, even though retrieval "worked."
  • The data already has the fix on hand: every chunk's rowParentGUID points at its full page — the page it was carved out of, which usually discusses both fiber types together.
  • The fix: after finding the best small chunk(s), swap them for their parent chunk(s) before sending anything to Claude. The small chunk finds the needle; the parent chunk gives the whole haystack around the needle, so the answer isn't cut off mid-thought.
Child chunk"Here's the exact sentence that matches."
Parent chunk"Here's the whole section that sentence lives in."
Diagram

How parent-chunk expansion fits the pipeline

Expansion runs last, after retrieval has already picked its winners — plain vector search, hybrid search, and/or rerank can all feed it, since they share the same row shape. For every retrieved child chunk, it looks up that chunk's parent by rowParentGUID and swaps the parent's text in — deduping when two winning child chunks point at the same parent.

Expansion never changes ranking or drops a chunk — it only swaps what text is attached to each row before build_expanded_context_block() renders the numbered excerpts Claude sees. If a parent row is somehow missing (shouldn't happen -- rowParentGUID is a foreign key), the original child chunk is kept as-is rather than silently dropped.

🔵 Child chunk (input)

~300–500 tokens, 10–15% overlap, built for embedding/keyword precision. Exactly what retrieve_chunks(), hybrid_search(), and rerank_chunks() already return.

row["rowJSON"]["text"] → the two-sentence soluble-fiber snippet

🟡 Parent chunk (after expansion)

The full page (recognised once via py/lrm/eda1_extract/recognize.py, stored in lrm_page_table), fetched by retrieval.read_page_row(rowParentGUID) and swapped into the same row shape — same keys, same ranking metadata, bigger text.

row["rowJSON"]["text"] → the whole "Fiber" section, both fiber types included
Reference

Dedup and sizing — the two things expansion has to get right

Comparison questions ("how does X differ from Y") routinely retrieve several winning child chunks from the very same section. Expanding each one independently would send Claude the same parent section two or three times over — wasteful, and confusing in the numbered excerpt list. Expansion fetches and sends each distinct parent exactly once.

Input (best-first)rowParentGUIDExpanded output
Child A — "…soluble fiber binds bile acids…"parent-421 expanded row — parent-42's full text, matched_children = [A, B]
Child B — "…insoluble fiber adds bulk to stool…"parent-42
Child C — "…fiber recommendations by age…"parent-91 expanded row — parent-9's full text, matched_children = [C]

The surviving row for a deduped parent keeps Child A's ranking metadata (whatever it carried in — rerank_score, rrf_score, cosine_distance, ...), since A is the best-ranked of the two — the same "first occurrence wins" rule reciprocal_rank_fusion() already uses when several ranked lists share a row.

Sizing: a parent chunk is a whole section, not a token budget

Chunks are capped at ~500 tokens by design (CHUNK_TOKEN_BUDGET in py/lrm/eda2_transform/build_chunks.py). Parent chunks aren't — a parent is one whole book section, which can run from a paragraph to several thousand words. Sending an oversized parent unchecked could quietly consume the entire context budget build_expanded_context_block() has to share across every excerpt.

expand_to_parent_chunks(chunks, max_parent_chars=6000) — the default — truncates a parent's text at 6000 characters (~1500 tokens) and appends a "...[parent chunk truncated for length]" marker. Pass max_parent_chars=None to disable truncation entirely.

Reference

Python API

No SQL migration needed — lrm_page_table, its rowParentGUID foreign key on the child table, and retrieval.read_page_row() already exist. This is purely a query-time Python step. 

# low-level: expand whatever a prior retrieval step already returned
from reusable_code import retrieve_chunks, rerank_chunks, expand_to_parent_chunks, build_expanded_context_block

candidates = retrieve_chunks("How does soluble fiber's effect on LDL differ from insoluble fiber's?", match_count=15)
top        = rerank_chunks("...", candidates, top_n=5)
expanded   = expand_to_parent_chunks(top)                    # dedup + swap in parent text
context    = build_expanded_context_block(expanded)          # same numbered-excerpt shape, + parent title

# end-to-end, composes with hybrid search and reranking (runs last, after both):
from reusable_code import ask_question
result = ask_question("...", expand_to_parents=True)                                    # plain retrieval, then expand
result = ask_question("...", use_hybrid=True, use_rerank=True, expand_to_parents=True)   # hybrid + rerank + expand
result = ask_question("...", expand_to_parents=True, max_parent_chars=None)                    # disable truncation

See py/ipynb/stage2_ask_examples4_parent_chunk_expansion.ipynb for worked examples, and py/reusable_code/README.md for the one-paragraph summary.

Final answer

Claude Sonnet, now able to answer the full comparison

Soluble fiber lowers LDL cholesterol by binding bile acids in the gut, forcing the liver to pull more cholesterol from the blood to synthesize replacement bile acids. Insoluble fiber has little to no effect on LDL — instead it adds bulk to stool and speeds transit time. Without expansion, only the first mechanism would have been available to Claude; the swapped-in parent section carries both.
